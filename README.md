# 3D Viewer

> 零依赖的 WebGL2 三维查看器，用于网格与点云的双窗并排对比。无需构建，开箱即用。

![双窗并排对比：左窗点云按方向着色，右窗点云叠加在灰色 ghost 上](docs/images/dual-window.png)

纯原生 JavaScript + WebGL2 实现，没有框架、没有打包步骤、没有 npm 依赖。

**在线演示**：<https://anonymous772066235.github.io/3DViewer/>（GitHub Pages 静态发布，查看 / 配准 / 测量 / 裁剪 / 导出均可使用）。

本地使用：双击 `serve.bat` 打开可获得完整能力（独立线程配准、路径载入）；直接双击 `index.html` 也能看模型，但导入与配准回退主线程、大文件会卡（见[两种打开方式](#两种打开方式推荐-servebat)与[性能差异](#性能差异)）。

## 核心：两份数据并排对比

这是工具的出发点——**左窗放一份、右窗放一份，同屏对照**。

上图是 Stanford Bunny 点云：左窗按法向着色（RGB 对应 XYZ 方向），右窗把另一份点云叠加在灰色 ghost 上——同一模型、两份数据，靠颜色和透明度一眼分出差异。两侧相机同步，转任意角度都保持同一视角。

能对比的组合不限于网格与点云：

| 左窗 | 右窗 | 典型用途 |
|---|---|---|
| 点云 | 点云 | 两次扫描的形变、点云配准（上图） |
| 网格 | 网格 | 两版模型对比 |
| 网格 | 点云 | 扫描结果 vs CAD 模型，判断偏差 |
| 任意 | 任意 | 两个工件的并列查看 |

两侧视口可以**独立相机**（各转各的），也可以**同步相机**（严格同角度），还可以把一侧作为半透明叠加层投到另一侧。右下角有随画面缩放的比例尺，左下角在视口变化时短暂显示该窗的像素尺寸。

### 两种数据对不上时：数据对齐

![数据对齐面板：ICP 把 bun045 对齐到 bun_zipper，RMS 收敛到 0.0000](docs/images/data-align.gif)

扫描件与 CAD 模型往往不在同一姿态。侧栏「数据对齐」提供三种手段：

- **N-N**：在两层上各点若干对应点，实时显示 RMS 与逐点残差，凑够 3 对即可求刚体变换
- **ICP**：局部精配准；姿态差大时先勾选 `4PCS` 做全局粗配准
- **矩阵**：直接编辑 4×4 矩阵并应用，也可取逆矩阵回退

配准是**确定性**的：同一对图层重复运行会得到同一个结果，第二次起几乎零增量，不会越配越歪；若本轮没有改善，会提示并保持原位。

配准结果写入目标图层的顶点数据，可以接着做裁剪、测量或导出。

**用 URL 直接复现这两种布局**：

```
# 双窗并排，且相机同步
index.html?sync=1&url=model.stl&slot=A&url2=model_points.xyz&slot2=B

# 同屏叠加（单窗）
index.html?single=1&url=model.stl&slot=A&url2=model_points.xyz&slot2=B
```

| 参数 | 说明 |
|---|---|
| `url` / `slot` | 第一个文件与槽位（`A` 左 / `B` 右 / `BOTH` 两侧） |
| `url2` / `slot2` | 第二个文件与槽位，两个文件**串行加载**，互不覆盖 |
| `single` | `1` = 单窗口（所有图层在同一视口） |
| `sync` | `1` = 双窗共享相机，左右严格同角度 |
| `zoom` | 相机距离倍数，`< 1` 为放大，用于看局部细节 |
| `target` | `x,y,z`，镜头对准的坐标，配合 `zoom` 定点放大 |

## 特性

| | |
|---|---|
| **双窗并排** | 左右两个独立视口各放一份数据，相机可独立或同步；支持把一侧作半透明叠加层投到另一侧 |
| **多格式** | STL（binary / ASCII）、OBJ、PLY、OFF、GLB / glTF、PCD（ascii / binary）、点云文本（xyz / csv / txt / pts …） |
| **三维裁剪** | 矩形 / 多边形框选，空格连续追加选区，一次拆成「选中」与「剩余」两个图层 |

| **标量场着色** | 点云按字段着色，带色标条与分布直方图 |
| **深浅主题** | 深色 / 浅色一键切换，标注色跨主题一致 |
| **视口角标** | 右下角常驻比例尺；左下角在视口变化时短暂显示像素尺寸 |

## 快速开始

### Windows

```bat
双击 serve.bat
```

浏览器自动打开 `http://127.0.0.1:8765/`。

### 手动启动

```bash
python server/serve.py
```

可选环境变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `VIEWER_PORT` | `8765` | 本地服务端口 |
| `VIEWER_NOBROWSER` | — | 设为 `1` 则不自动打开浏览器 |

### 两种打开方式：推荐 `serve.bat`

界面也可以直接双击 `index.html` 打开，但**功能并不等价**：

| 功能 | 在线（Pages） | `serve.bat`（http） | 双击 `index.html`（`file://`） |
|---|---|---|---|
| 载入、渲染、视角、拾取、测量、裁剪、导出 | ✅ | ✅ | ✅ |
| 数据对齐（N-N / ICP / 4PCS） | ✅ 独立线程 | ✅ 独立线程 | ⚠️ 回退主线程，迭代期间界面会卡 |
| 导入解析 / 预处理 / 拾取索引 | ✅ 后台线程 | ✅ 后台线程 | ⚠️ 回退主线程，大网格载入/首点会卡 |
| 线框 / 法向 / 边界生成 | ✅ 主线程分帧 + 进度条 | ✅ 主线程分帧 + 进度条 | ✅ 主线程分帧 + 进度条（无 Worker 差异） |
| 属性面板显示文件绝对路径 | ❌ 静态托管无 `/locate`（已跳过请求） | ✅ 走 `/locate` | ⚠️ 需额外启动本地服务 |
| `?url=` 载入仓库内相对路径 | ✅ | ✅ 任意本地路径 | ❌ 浏览器禁止 `fetch` 本地文件 |
| 「载入历史」按路径重开 | ⚠️ 文件句柄类可用 | ✅ | ❌ 条目还在，但点不开 |
| 需要 Python | ❌ | ✅ | ❌ |

原因（实测，不是兼容性玄学）：

```
new Worker('js/worker_align.js')    // 4PCS 粗配准 + 候选验证 + ICP 精配准
new Worker('js/worker_io.js')     // 解析 + 预处理 + 拾取索引
  → SecurityError: Script at 'file:///…' cannot be accessed from origin 'null'
fetch('js/core.js')
  → TypeError: Failed to fetch
```

浏览器只在 `http(s)` 源下允许创建 `Worker`，也禁止 `file://` 页面 `fetch` 本地文件。
`file://` 下启动时日志面板会记一条 `warn` 提示能力降级，不再静默。
两个后台线程分别承担：4PCS 粗配准 + 候选验证 + ICP 精配准（`worker_align`）、导入解析 / 预处理 / 拾取索引（`worker_io`，与主线程共用内核）；
`file://` 下二者回退主线程。线框 / 法向 / 边界为**主线程分帧计算 + 进度条**（三者行为一致，不受协议影响），
不会阻塞渲染，但缺少 Worker 并行。

### 性能差异

三种打开方式的渲染结果一致（均为全量原始几何 + 视锥剔除），差异集中在**计算放在哪个线程**：

| 环节 | 在线（Pages, https） | `serve.bat`（http 本地） | 双击 `index.html`（`file://`） |
|---|---|---|---|
| 渲染 / 视角 / 视锥剔除 | 主线程，三者相同 | 主线程，三者相同 | 主线程，三者相同 |
| 导入解析 / 预处理 / 拾取索引 | Worker 后台 | Worker 后台 | 主线程，大文件载入时界面卡顿 |
| 配准迭代（ICP / 4PCS） | Worker 后台 | Worker 后台 | 主线程，迭代期间无法流畅拖拽视角 |
| 线框 / 法向 / 边界 | 主线程分帧 + 进度条 | 主线程分帧 + 进度条 | 主线程分帧 + 进度条 |
| 网络开销 | 远程下载 JS/CSS（有 CDN 缓存） | 本地回环，最快 | 本地磁盘读取，无网络 |

要点：

- **Pages vs serve.bat**：两者计算能力相同（Worker 都可用），差别只在资源加载——Pages 走公网（首次稍慢、后续走浏览器缓存），`serve.bat` 走 `127.0.0.1` 本地回环最快。Pages 是纯静态托管，无 `/file` / `/locate` / `/optimize` 后端，插件「孔位优化」不可用并给出提示。
- **file:// vs 前两者**：渲染与辅助线体验相同（分帧 + 进度条），但**导入与配准回退主线程**：大网格载入、ICP 迭代期间界面会明显卡顿。日常查看模型无差异，处理大文件或跑配准请用 `serve.bat`。
- **全量几何**：三种方式都加载完整原始网格，不做有损简化；可见性由视锥剔除 + 近→远排序控制，字段名/几何精度一致。

> **在线版开箱即用**：把链接发给别人就能看模型、做配准、测量和导出（需要数据自行拖入）。
> **本地完整能力**用 `serve.bat`：多出 `/file` 路径载入、`/locate` 路径反查，不需要额外启动任何东西。

### 加载数据

三种方式任选：

1. 顶栏 **载入** → 选择文件
2. 把文件**拖到窗口**里
3. URL 直达：`index.html?url=<相对路径>&slot=B`

**载入菜单里保留最近 10 个**，点一下即可重开，不用再翻目录。

浏览器出于安全不会把文件的真实路径交给网页，所以「重开」不依赖路径，而是三种手段：

| 来源 | 记住什么 | 重开方式 |
|---|---|---|
| 拖入 / 选择（Chrome、Edge） | **文件句柄**（`FileSystemFileHandle`，存在 IndexedDB） | 直接读回同一个文件，任意目录都行，不靠猜 |
| 拖入 / 选择（其它浏览器） | 服务按「文件名 + 大小」反查的绝对路径 | `GET /file?path=` 回读 |
| `?url=` 载入 | 完整地址 | 直接再取 |

句柄是一条真实引用，不是路径字符串——所以桌面、U 盘、网络盘里的文件都能重开，
代价是每次会话首次打开时浏览器会问一次「是否允许读取该文件」。

三种都拿不到的条目会置灰标注「需重新选择」，不会留一个点了没反应的死条目。

## 支持格式

| 类型 | 扩展名 | 说明 |
|---|---|---|
| 三角网格 | `.stl` | binary / ASCII；STL 无共享顶点信息，加载时按坐标去重（约省 80% 顶点） |
| 三角网格 | `.obj` | 保留原始 `v` / `f` 拓扑，不做顶点合并 |
| 三角网格 | `.ply` | ASCII / binary |
| 三角网格 | `.off` / `.coff` | 任意边形按扇形三角化；COFF 读取顶点色 |
| 三角网格 | `.glb` / `.gltf` | glTF 2.0；GLB 自包含，`.gltf` 需内联 `data:` buffer；自动把 Y 轴向上转成 Z 轴向上 |
| 点云 | `.pcd` | ascii / binary；读取 `rgb` 字段并解包成顶点色 |
| 点云 | `.xyz` `.csv` `.txt` | 空白或逗号分隔，支持额外标量列 |

PLY / OBJ / OFF / glTF **可以只有顶点、没有面**：按点云载入，不会报「没有可显示的数据」。OBJ 的 `v x y z r g b` 顶点色与 COFF 顶点色都会保留。

超过内存预算时会在加载前弹窗确认，可选择按比例下采样。

## 导出

顶栏「导出」（快捷键 `Shift+S`）按**当前选中图层**决定可用项，用不了的项会置灰并说明原因。

| 项 | 适用 | 说明 |
|---|---|---|
| 原始文件 | 任意 | 载入时的原始字节，未经任何处理 |
| STL（binary） | 网格 | 面法向由叉积现算，不依赖源数据 |
| OBJ | 网格 | 复用载入时算好的唯一顶点表，顶点数不会翻倍 |
| PLY | 网格 / 点云 | binary；网格带面表，点云带颜色与标量 |
| GLB | 网格 | glTF 2.0 单文件，自动转成 Y 轴向上 |
| 点云 CSV / XYZ | 点云 | 有标量场时按列追加 |

导出**只反映当前内存中的数据**：经过矩阵应用、裁剪拆分后的图层，导出的是处理结果，
需要原始字节请用「原始文件」（它始终是载入时的那一份）。

大文件按块拼接 Blob，几百万三角形也不会出现一次性字符串拼接导致的内存峰值。

## 界面

```
┌──────────────────────────────────────────────────────────┐
│ 3DV  3D Viewer                        载入 双窗 截图 清空  │
├────────────┬─────────────────────────────────────────────┤
│ 场景树      │                                             │
│  A 左侧     │                                             │
│  B 右侧     │              视口（单窗 / 双窗）             │
│  S 公共     │                                             │
├────────────┤                                             │
│ 图层属性    │                                             │
│ 视图设置    │                                             │
│ 数据对齐    │                                             │
└────────────┴─────────────────────────────────────────────┘
```

**槽位含义**：`A` 左侧、`B` 右侧、`S` 公共（两侧同时显示）。图层可在槽位间移动或拷贝，移动后可作为对面模型的半透明叠加层（ghost）。

**场景树**：支持父子层级。网格加载后显示 `72.7k 面 · 38.4k 点`；选中网格后其下方出现 `vertices` 子项，点击查看顶点数与包围盒，右键可把顶点拷成点云图层。

**侧栏**：可左右拖拽调宽（220~620px）；场景树与下方属性区之间可上下拖拽，各自独立滚动。
下方三个标签页（图层属性 / 视图设置 / 数据对齐）共用一套排版：分组标题、行高、标签左对齐、勾选框右对齐。

### 键盘

| 按键 | 功能 |
|---|---|

### 三维裁剪流程

```
工具 ▾ → 裁剪
   ↓
框选（矩形 / 多边形）→ 高亮显示选中部分
   ↓
空格 或「继续裁剪」→ 保留高亮，追加下一块（可重复）
   ↓
应用裁剪 → 拆成 _segmented / _remaining 两个图层，退出裁剪
```

裁剪产生的两个图层是完整的几何体，可继续参与后续裁剪或优化。

## 大文件与内存

加载前按文件大小预估内存占用，超出预算会弹窗：

| 选项 | 行为 |
|---|---|
| 取消 | 不加载 |
| 下采样 | 按比例抽样三角形 / 点，并在状态栏标注“已抽样” |
| 强制加载 | 忽略预算（显存不足时 GL 会拒绝并给出提示） |

调试参数：`?memlimit=<MB>`、`?maxpts=<N>`、`?maxtri=<N>`。

## 目录结构

```
3DViewer/
├── index.html            单页入口
├── serve.bat             一键启动本地服务
├── README.md / CHANGELOG.md / LICENSE
├── assets/
│   └── icons/            运行时图标（favicon + 顶栏标记）
├── css/style.css         深浅两套主题变量
├── js/                    平铺 + 文件头分类标签（[L1]…[P]）
│   ├── core.js            [L1·基础]   数学 / 相机 / KD 树
│   ├── worker_io.js       [L2·IO]     解析 / 预检 / 导出（主线程+Worker 共用）
│   ├── algo.js            [L3·算法]   裁剪 / 拾取 / ICP / 4PCS
│   ├── render.js          [L4·渲染]   WebGL / 拓扑 / 视角器
│   ├── ui.js              [L5·界面]   面板 / 场景树 / 工具
│   ├── app.js             [L6·编排]   状态 / 加载 / 快捷键（含原 keys.js）
│   ├── worker_align.js      [W·后台]    4PCS 粗配准 + 候选验证 + ICP 精配准
│   └── optimize.js        [P·插件]    扩展入口（含原 registry.js）
```

**分层约定**：文件头第一行的 `[L1·基础] … [P·插件]` 即分类与依赖契约；下层不依赖上层，`app.js` 编排全部，`workers` 独立计算。
