# 3D Viewer

通用三维查看器：**导入 / 查看 mesh 与点云，左右双视图对比（如优化前 / 优化后），并用层级树叠加控制显示**。

零第三方依赖（不联网、不加载 CDN），纯 WebGL2 实现，可离线使用。

---

## 1. 打开方式

| 方式 | 操作 | 说明 |
| --- | --- | --- |
| 直接打开 | 双击 `index.html` | 推荐 Chrome / Edge（需支持 WebGL2） |
| 本地服务 | 双击 `serve.bat` | 默认 <http://127.0.0.1:8765/>，浏览器对 `file://` 有限制时使用 |

---

## 2. 支持格式

| 类型 | 扩展名 | 说明 |
| --- | --- | --- |
| Mesh | `.stl` | 二进制 / ASCII 自动识别 |
| Mesh | `.obj` | 支持 `f` 的 `v`、`v/vt`、`v//vn` 与负索引、多边形扇形三角化 |
| Mesh | `.ply` | ASCII / binary_little_endian；带 `face` 为 mesh，只有 `vertex` 为点云 |
| 点云 | `.txt` `.xyz` `.csv` `.asc` `.pts` `.dat` | 空白 / 逗号 / 分号 / 竖线分隔 |

点云列语义识别（**列数 > 3 时导入会弹出确认框**）：

| 情况 | 行为 |
| --- | --- |
| 列数 = 3 | 直接按 `x y z` 解析，不弹窗 |
| 列数 > 3 | 弹窗逐列确认含义：**前三列固定为 X / Y / Z**；默认规则 —— 超过 6 列时第 4~6 列默认为**法向** `Nx/Ny/Nz`，其余列（以及总列数 ≤ 6 时）默认为**标量场**；若表头明确写了 `R/G/B` 则默认按颜色，写 `Label/Id/Tag/Class/Hid` 则默认标签 |
| 弹窗可选含义 | 法向 X/Y/Z、颜色 R/G/B、标签/ID、**标量场（可多列）**、忽略；法向必须三列齐全、颜色必须三列齐全，否则提示；可「取消导入」 |
| 表头 | 支持 `//X Y Z R G B Scalar field`、`# x y z nx ny nz`、无前缀的纯文本列名；列名与首行样例值会显示在弹窗中辅助判断，含空格的名字（如 `Scalar field`）会自动合并为一列 |
| PLY | 自带结构，直接读取 `nx/ny/nz`、`red/green/blue` |

识别到的属性显示在图层属性「统计」中（如 `POINTS(text) · 5.0k 点 · 法向 · 标量场 SF1`）。

**若识别到标量场，导入后默认按「标量场（彩虹）」着色**并显示色条与直方图（没有标量场时默认单色）。着色下拉可切换：单色 / 按高度 / 按法向 / 按标签 / 顶点色 / 标量场（彩虹）；多标量场可在「标量场」下拉切换，画布右下角与图层属性面板**同时显示分布直方图**（柱色跟随当前色带，白色竖线标出当前显示范围）与数值范围。

## 3. 界面与操作

### 3.1 双视图
- 画布左右各一个独立相机，默认 **左 = 左侧(A)**、**右 = 右侧(B)**；
- “视图设置”可改变每个视图显示哪些槽位（A / B / 公共 S），支持任意叠加；
- 勾选「**叠加对面模型**」后，用右侧两个单选项选择叠加方式：**透明**（半透明灰轮廓，便于位置对照）/ **实体**（对面模型**完全按它当前的显示状态**绘制：颜色、线框、顶点、法向、着色模式、透明度，与本体一起参与深度；由于同模型属性双向共享，两侧表现完全一致）；
- 「左右相机同步」**默认开启**（两个视图共用同一相机对象，旋转、平移、缩放、自适应完全一致）；取消后各自独立；
- 顶栏「**单窗口 / 双窗口**」按钮一键切换视口数量：单窗口时 A / B / 公共 S 全部图层在同一画面渲染（只做一次渲染，性能更好），左右标签与分割线隐藏，`载入` 按钮自动变为 `载入 A` / `载入 B`（“载入 两侧”隐藏），图层树结构与叠加关系保持不变；再次点击即恢复双窗口。
- **光照方向**：「光照跟随相机」默认开启（头灯，转到哪面哪面亮）；取消后可分别调整「光照方位 / 光照俯仰」（世界坐标，Z 轴向上），用于侧光 / 逆光检查形貌与法向。
- **视角器（截角六面体）**：画布左下角是随相机旋转的**正六面体削掉 8 个角**的模型 ——6 个原面（削角后为八边形）+ **8 个正三角形角面**（对应 `XYZ` 体对角线视角）；12 条棱的中点另有**小圆点热区**（对应 `XY / YZ / XZ` 的 45° 视角），共 **6 + 8 + 12 = 26 个可点击视角**；中心向外画出 **X（红）/ Y（绿）/ Z（蓝）正方向箭头**（带字母，正对观察者时缩为圆点）；悬停高亮，点击即切到该方向，状态栏显示名称（`Z+`、`XY 向 (0.71, 0.71, 0)`、`XYZ 向 (0.58, 0.58, 0.58)`）。
- **同一模型两侧状态一致**：用「载入 两侧」或先后载入同一个文件时，A / B 两个图层**共享一份显示属性**（面片色、背面色、线框色、顶点色、显示开关、着色模式、透明度、点大小、标量场范围/色带等），改任一侧另一侧立即同步，保证同一模型在左右两侧的表现完全相同。
- **地面网格与坐标轴**按**全场景包围盒**生成，左右视图的网格格距与坐标轴长度始终一致。

### 3.1.1 槽位 A / B / S 的含义

每个载入的文件都会分配到某个**槽位**，两个视图各自按槽位决定渲染哪些图层：

| 槽位 | 含义 | 左视图默认 | 右视图默认 |
| --- | --- | --- | --- |
| `A` | 「载入 左侧 (A)」载入的图层 | 显示 | 不显示（若开“叠加对面模型”则以 ghost 出现） |
| `B` | 「载入 右侧 (B)」载入的图层 | 不显示（同上，可 ghost） | 显示 |
| `S` | 公共 / 共享图层 | **显示** | **显示** |

- 图层属性里的「归属」可随时把某层改到 A / B / S；
- **拖放识别**：整个窗口都可接收文件（画布、标签栏、场景树、属性面板皆可落点），按**鼠标所在半屏**决定导入 A 还是 B；拖动时左右半屏会**高亮提示**「松开导入到左侧/右侧」，单视图模式一律导入 A；
- 视图与槽位固定对应：**左视图渲染 `A + S`，右视图渲染 `B + S`**（界面不再提供槽位勾选）；想看到对面的模型，用「叠加对面模型」的透明/实体模式；
- 典型用法：A 放优化前、B 放优化后，`S` 放参考网格或点云，两侧都能看到同一基准。

### 3.2 场景树（层级叠加）
- 三个根：`左侧(A)`、`右侧(B)`、`公共图层(S)`；
- **鼠标悬停任意图层节点**会显示：名称、类型、面数/点数、文件名、大小、修改时间、**磁盘路径（能解析时）**、归属与显示状态；
- 每个图层行末尾的 `×` 可**移除该图层**（释放显存并从场景树删除）；也可选中后按 `Delete`，或用属性面板底部的「移除该图层」按钮；
- **右键图层行**弹出上下文菜单：可「**移动到** 左侧/右侧」或「**拷贝到** 左侧/右侧」（A 层给 B，B 层给 A，公共图层 S 给出两个目标）。移动只改归属；拷贝会新建一个图层（**共享几何与显存**，`refs+1`，显示属性为独立副本，互不影响）；
- **结果图层挂在源图层下一级**：裁剪产生的 `*_segmented` / `*_remaining`、孔位优化产生的 `*_oh.obj` 都会缩进显示在源图层之下（带 `└` 连接符）；删除源图层会**级联删除**其所有结果；
- 每个图层可单独勾选显示、改色、改透明度、删除；
- 双击图层：相机聚焦到该图层包围盒。

### 3.3 图层属性
| 控件 | 适用 | 说明 |
| --- | --- | --- |
| **配色…**（按钮 + 浮层） | 全部 | 「外观」组只占两行：`配色…` + `不透明度`。点按钮弹出小浮层，内含 **面片（正面）/ 背面 / 线框 / 顶点 / 边界** 五个色块；按钮左侧的小色点实时显示当前主色。浮层逻辑：`pointerdown` 阻止冒泡 → **点色块不会关闭浮层**（可连续调整多个颜色），点浮层外或按 `Esc` 才关闭；`?colors=1` 可默认展开 |
| 面片颜色（正面）/ 不透明度 | 全部 | 逐层独立（点云上显示为“点颜色”） |
| 背面颜色 | mesh | 与正面颜色独立设置，正向/背向三角形分两遍绘制，各自取色 |
| 线框颜色 | mesh | 逐层独立取色，默认亮蓝 |
| 顶点颜色 | mesh | 逐层独立取色，默认近白 |
| 边界颜色 | mesh | 逐层独立取色，默认亮青（`#22d3ee`），便于在橙色面片上分辨 |
| 点大小 | 点云 | 1~24 px |
| 着色（点云） | 点云 | 单色 / 按高度 / **按法向**（法向编码为 RGB，并按“法向 vs 视线”做朝向衰减，**背向视线的点为黑**，与 CloudCompare 一致）/ 按标签 / 顶点色 / 标量场（彩虹） |
| 标量场 | 点云 | 检测到标量场时出现，可在多个字段间切换；选中“标量场”着色后画布右下角显示**色条**（字段名 + 最小/最大值） |
| 范围 | 点云 | 标量场着色的上下限，可直接输入数值（留空 = 自动取数据 min/max），`自动` 按钮一键恢复；超出范围的点按端点色显示（与 CloudCompare 一致） |
| 路径 | 全部 | 显示数据来源：`?url=` 载入显示完整 URL；本地拖入的文件由 `/locate` 按「文件名 + 大小」在 `HoleOptimize/data` 下反查实际磁盘路径（查不到时标注“未解析”，浏览器本身不提供本地绝对路径） |
| 色带 | 点云 | 4 种色带：**蓝-青-绿-黄-红（Jet）** / 蓝-绿-红 / 灰度 / 蓝-白-红；着色器与右下角色条同步切换 |
| 着色（mesh） | mesh | 光照（片元内用 `dFdx/dFdy` 求面法向做漫反射，**正面用面片颜色、背面用背面颜色**，可据此发现绕序翻转的面）/ 纯色 / **按法向（背面黑）**（正面显示法向 RGB，背面直接黑，与点云的“按法向”一致） |
| 显示（面片 / 线框 / 顶点 / **边界**） | mesh | 四个**互相独立**的开关，可单独显示其中任意一种或任意组合 |
| 边界 | mesh | 只被 **1 个三角形**使用的边（模型开放边界 / 破洞），用独立颜色高亮，与面片/线框/顶点同级的开关；封闭模型无边界可显示。首次勾选时按坐标去重后统计一次（结果缓存在图层上），「统计」里会显示边界边数 |
| 顶点大小 | mesh | 1~16 px |
| 面法向 | mesh | 勾选后**逐个面实时计算面法向**并绘制（不依赖文件是否带法向），长度 = 平均边长 × 1.2 × 倍率，青色线段 |

### 3.4.1 三维编辑：框选 / 多边形 / 拆分

顶栏「**工具 ▾**」下拉菜单（**拾取与裁剪同级**，均在其中；`Esc` 收起菜单并退出编辑）：

```
工具 ▾
  拾取            P
  ─────────────
  裁剪
  矩形选择
  多边形选择
  应用拆分
  取消
```

| 步骤 | 操作 |
|---|---|
| 1 | 在场景树中**选中**要编辑的图层（网格或点云） |
| 2 | 点「矩形」→ 在画布上**拖出方框**，松手即预览；点「多边形」→ **单击加点，双击闭合**（Enter 也可） |
| 3 | 预览：网格被选中的部分以**半透明青色**高亮；点云在状态栏显示「选区 N 点 / 剩余 M 点」（点云不做 GPU 高亮，避免与属性状态冲突） |
| 4 | 点「应用拆分」→ 生成 `<名称>_segmented` 与 `<名称>_remaining` 两个新图层，**缩进挂在源图层下一级**，**原图层自动隐藏**，选中新拆出的部分 |

算法（对齐 CloudCompare 的 segment 思路）：

- 选择多边形按当前视图**反投影为过视点的棱柱平面**（每条屏幕边一个半空间）；
- 网格：对每个三角形依次用这些平面做**半空间裁剪** —— 交集多边形三角化后进 `segmented`（**切口是精确的**），`remaining` 由差集分解得到（逐平面收集“外侧”碎片，两部分**不重叠、不裂缝**）；
- 点云：把每个点代入棱柱半空间判断内外，直接按索引分成两份（保留法向 / 标签 / 标量场，并按子集重算 min/max）；
- 裁剪结果缓存在内存，点「应用拆分」才真正建成图层（预览不修改源数据）。

| 参数 | 说明 |
| --- | --- |
| `demo=seg` | 载入后自动框选一块并预览（自测用） |
| `segapply=1` | 与 `demo=seg` 联用，预览后立即应用拆分 |

关闭方式：`js/segment.js` 顶部 `var ENABLE_SEGMENT = false;`，或注释 `index.html` 中两处 `===== 三维编辑 BEGIN/END =====`。

### 3.4.2 拾取与测量

开启拾取模式（顶栏「拾取」按钮或按 `P`）后，在模型或点云上单击即可取点，**最多保留最近 3 个点**：

| 显示项 | mesh | 点云 |
| --- | --- | --- |
| 坐标 | 射线与三角形的交点 | 命中的点坐标 |
| 法向 | 该三角形的面法向（三点叉积） | 文件自带的点法向 |
| 标签 | — | `tags` 列（如孔 id） |
| 标量 | — | 所有标量场的该点取值（含字段名） |
| 归属 | 图层名 + 类型（网格 / 点云） | 同左 |

自动计算（面板底部分隔线下方）：

| 点数 | 结果 |
| --- | --- |
| 2 点 | `距离 P1→P2`、`Δx / Δy / Δz` |
| 3 点 | 追加 `角度 ∠P1P2P3`（以 P2 为顶点，度）、`边长 P2P1`、`P2P3` |

- 3D 场景中每个拾取点画一个**十字标记**（黄 / 绿 / 蓝，对应 P1 / P2 / P3），关闭深度测试，任何视角都能看到；
- 十字**单臂恒定为 1 mm**（世界尺寸，不随场景缩放）；当 1 mm 在屏幕上不足 6 px 时按 6 px 绘制，保证远处也可见，放大到 1 mm ≥ 6 px 后即为真实 1 mm（可用 `?mark=` 改单臂长度）；
- 面板右上「清空」清除所有点，「×」关闭面板并退出拾取模式；`Esc` 同样退出；
- 超过 3 个点时自动丢弃最早的一个（保持“最近 3 点”）。
| 双击树节点 | 聚焦该图层 |
| `F` | 两视图自适应 |
| `W` | 选中 mesh 开关线框 |
| `N` | 选中 mesh 开关面法向 |
| `Esc` | 取消选中 |
| 拖放文件到左 / 右半屏 | 载入为 A / B |

顶部按钮：`载入 左侧 (A)`、`载入 右侧 (B)`、`载入 两侧`（同一文件同时进入 A/B，GPU 资源共享，不占双份显存）、`单窗口` / `双窗口`（一键切换视口数量，激活态高亮）、`自适应`、`截图`、`清空`。

### 3.4.3 截图与清空

| 按钮 | 行为 |
| --- | --- |
| `截图` | 立即重新渲染一帧并导出 `view_YYYYMMDD_HHMMSS.png`：**下载到浏览器默认下载目录**（页面脚本无法指定绝对路径，可在浏览器设置里改为“每次询问保存位置”）；若当前环境支持剪贴板（`https` 或 `http://localhost`），**同时写入系统剪贴板**，状态栏会明确提示结果 |
| `清空` | 弹出**二次确认对话框**（`清空全部 N 个图层？该操作不可撤销。`），点「确定」才执行；`Esc`、点「取消」或点遮罩层均可取消 |

> 剪贴板说明：`navigator.clipboard.write()` 需要安全上下文。用 `serve.bat`（`http://127.0.0.1:8765`）或 `https` 打开可用；直接双击 `index.html`（`file://`）时浏览器会拒绝，此时只下载文件，状态栏提示“剪贴板不可用”。

### 3.5 链接直接打开（可选）

通过本地服务启动时，可用查询参数直接载入模型：


### 3.6 孔位优化（可选功能）

把「导入左侧 → 一键优化 → 结果自动进右侧」串起来的可选功能。浏览器不能直接执行本地程序，因此由 `bridge/optimize_server.py` 作为本机桥接服务调用 `HoleOptimize_cli.exe`。

| 项 | 说明 |
| --- | --- |
| 前置 | C++ 侧已构建：`HoleOptimize/build/Release/HoleOptimize_cli.exe`（找不到时自动回退 `build/Debug/`）；可用环境变量 `HOLEOPT_EXE` 指定 |
| 必需的输入 | 网格（STL/OBJ）+ **`edge_pts.txt`**（≥6 列 `x y z nx ny nz`）。前端会把同批导入的 `edge_pts.txt` 一起上传；未提供时服务端会按网格文件名在 `HoleOptimize/data/**` 中找同名文件，取其同目录的 `edge_pts.txt` |
| 启动 | **双击 `serve.bat` 即可**：一个进程同时提供页面（`8765`）与优化接口（`POST /optimize`，**与页面同源**）——只要页面能打开，优化一定可用；也可只双击 `server/start_bridge.bat`（独立桥接 `8790`，供 `file://` 场景） |
| 使用 | 导入网格 → 点顶栏「孔位优化」→ 完成后最终 OBJ 自动载入右侧，并在场景树中**缩进挂在被优化的源图层下一级**。**输入取“当前显示的网格”中最新启用/载入的那一个**（隐藏的图层、点云都不参与，也不看当前选中项）；优化产物（`*_oh.obj`）不会被再次选为输入，除非它是唯一可见的网格 |
| 中间产物 | **不生成**：每次调用都在系统临时目录里建 cfg（`S0_save = 0`）、跑完即整目录删除，项目目录不落任何中间文件 |
| 结果 | CLI 固定输出 OBJ，文件名 `<原网格名>_oh.obj` |
| 自检 | `python bridge/test_bridge.py`（不经过浏览器，直接验证 上传→CLI→返回 OBJ 的链路） |
| 端口/超时 | `HOLEOPT_PORT`（默认 8790）、`HOLEOPT_TIMEOUT`（默认 1800 s） |

**关闭方式（任选其一，可叠加）**

| 级别 | 操作 | 效果 |
| --- | --- | --- |
| 最快 | `js/optimize.js` 顶部 `var ENABLE_OPTIMIZE = false;` | 脚本直接返回，按钮点击无反应 |
| 彻底 | 注释 `index.html` 中两处 `===== 孔位优化 BEGIN/END =====` 包围块（按钮 + `<script>`） | 按钮消失、不发任何请求 |
| 服务侧 | 不启动 `server/start_bridge.bat` | 点击提示「优化失败：Failed to fetch」 |

**实现要点**

- 网格与 `edge_pts.txt` 一律复制到临时目录、用 ASCII 文件名（`input.stl` / `edge_pts.txt`）落盘，规避 C++ 侧对中文路径的兼容问题；
- `run.cfg` 中 `S0_mesh / S0_in / S0_out` 全部为绝对路径，避开「相对路径被拼到输出目录」的坑；
- 服务只监听 `127.0.0.1`，CORS 放开仅用于本机页面调用；不要把 8790 暴露到公网。

### 3.6.1 为什么不能“点按钮时自动启动服务”

浏览器安全模型**不允许网页启动本地进程**（JS 没有 `exec` / `spawn` 任何等价 API）。如果网页能随手执行本地 exe，任何钓鱼页都能在你机器上运行任意程序——这是浏览器的硬性红线，没有开关可绕过。

因此本项目的取舍是：**把“页面”和“优化接口”合并进同一个进程**（`serve.py`，端口 8765，`POST /optimize` 与页面同源）。

| 打开方式 | 点击「孔位优化」的结果 |
| --- | --- |
| 双击 `serve.bat`（→ `http://127.0.0.1:8765/`） | 直接可用，**不需要任何其它服务**（页面能打开 = 优化接口在） |
| 双击 `index.html`（`file://`） | 弹出说明弹窗：浏览器限制，请双击 `serve.bat` 后用 8765 地址打开（会说明原因与替代方案） |
| 只双击 `server/start_bridge.bat` | `file://` 页面也可用（前端自动回退到 `http://127.0.0.1:8790`） |

若希望**彻底免手动启动**，把服务注册为当前用户登录自启（一次性，之后开机即在后台）：

```bat
reg add "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v ViewerServe /t REG_SZ ^
  /d "\"C:\Python310\python.exe\" \"D:\tools\viewer3d\serve.py\"" /f
```

取消自启：`reg delete "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v ViewerServe /f`
（把其中的 Python 路径与 `serve.py` 路径换成你机器上的实际路径。）

### 3.6.2 中文路径与编码

全链路按 UTF-8 处理，中文目录 / 中文文件名 / 中文日志均直接可用：

| 环节 | 处理方式 |
| --- | --- |
| 前端 → 服务 | 文件名走 `X-Mesh-Name` 请求头（URL 编码），服务端 `urllib.parse.unquote` 还原 |
| 服务端落盘 | **保留原始中文文件名**（仅替换 Windows 非法字符 `\ / : * ? " < > |`）；若该环境运行失败且名含非 ASCII，自动改用 ASCII 名重试一次，日志会写明 |
| 配置与调用 | `run.cfg` 以 UTF-8 写盘、三个路径均为绝对路径；C++ 侧 `open_file_utf8`（UTF-8→UTF-16 + `CreateDirectoryW`）读写，因此中文目录、中文输出文件名都支持 |
| 结果回传 | 响应头 `X-Result-Name` 做 URL 编码，前端 `decodeURIComponent` 还原中文 |
| 日志文件 | `bridge/bridge.log` 固定 UTF-8 |
| 终端输出 | `serve.bat` / `start_bridge.bat` 先 `chcp 65001`；服务端 `sys.stdout.reconfigure(encoding='utf-8', errors='replace')`；CLI 子进程输出按 **UTF-8 → GBK** 依次尝试解码 |
| HTTP 访问日志 | 覆盖 `log_message`，先 `unquote` 再写日志，因此日志里是 `GET /locate?name=1.0-孔位工件_oh.obj` 而不是 `%E5%AD%94...` |

实测（`data/孔位工件/1.0-孔位工件.stl`）：

```
POST /optimize  mesh=1.0-孔位工件.stl (3634784 bytes)  edge=no
  edge -> 自动匹配 D:\...\data\孔位工件\edge_pts.txt (9513671 bytes)
  run  -> #1 mesh=1.0-孔位工件.stl  (原名 1.0-孔位工件.stl)
  cli  -> exit=0  2.0s  outputs=1
OK   1.0-孔位工件.stl -> 1.0-孔位工件_oh.obj  (2.0s, 2957846 bytes)
[http] "GET /locate?name=1.0-孔位工件_oh.obj&size=2957846 HTTP/1.1" 200 -
```

**关于“绝对路径”**：浏览器**不向网页暴露本地文件的真实路径**——`File` 对象只有 `name / size / type / lastModified`，这是 W3C 规范与各浏览器一致的安全设计（防止网页枚举本地目录）。因此本地拖入的文件由 `GET /locate?name=&size=` 反查：服务端在**搜索根**下按「文件名 + 大小」匹配，命中即返回绝对路径。

| 搜索根 | 说明 |
| --- | --- |
| `HoleOptimize/data` | 默认，递归 |
| `HOLEOPT_SEARCH` | 额外目录，多个用 `;` 分隔，需在启动服务前设置 |

```bat
set "HOLEOPT_SEARCH=D:\models;E:\点云数据"
serve.bat
```

`GET /health` 的 `search` 字段可确认当前生效的搜索根。

### 3.7 载入前的内存预估与下采样

每次载入前都会**先估算规模**，超出预算就弹窗让你决定，不会等浏览器崩了才发现。

### 估算与预算

| 项 | 依据 |
| --- | --- |
| 规模 | binary STL 读头部 84 字节拿**精确三角数**；ASCII STL / OBJ / PLY / 点云按文件大小 + 每单位字节数启发式估算 |
| 预计占用 | `count × (mesh?36:12) 字节 × 1.7`（1.7 覆盖解析中间数组、上传副本、索引缓冲） |
| 预算 | 优先 `performance.memory.jsHeapSizeLimit × 25%`；否则 `navigator.deviceMemory × 12%`；夹在 **512 MB ~ 2.5 GB** |
| 覆盖 | `?memlimit=<MB>` 强制指定预算（调试 / 特殊机器） |

### 弹窗

```
数据较大 — 建议下采样                                  ×
  文件      m05.stl
  规模      约 313,834 个三角形 · 按 STL 头部精确读取
  预计占用  18.3 MB
  内存预算  5.00 MB
  ▬▬▬▬▬▬▬●▬▬▬▬▬▬▬▬▬▬▬  25%
  下采样后约 78,459 三角形，预计占用 4.58 MB（在预算内）

              [取消]  [仍然全量导入]  [下采样导入]
```

- 滑杆 **5%~100%**，每隔 5% 一档，拖动时**实时**显示抽样后的数量与占用，并标注是否回到预算内；
- 打开时自动给出一个“刚好降到预算内”的建议比例；
- 「仍然全量导入」跳过抽样（明确的自担风险）；
- 「取消」直接不载入该文件（批量拖入时只跳过这一个）。

### 抽样方式

| 类型 | 方式 |
| --- | --- |
| 二进制 STL | 按 `step = ceil(总面数 / 目标面数)` **等间隔抽样三角形**，每个三角形保持完整（不撕裂） |
| ASCII STL / OBJ / PLY | 超过目标面数时**截断**并提示“仅载入前 N 个三角形” |
| 点云 | 按行号 `step` 等间隔抽样（**空间均匀**，不是只保留前 N 个），法向 / 标签 / 标量按同一行同步取舍 |

载入完成的提示会写明抽样情况，例如：`STL(binary) · 52.3k 三角形 · 按 1/6 抽样`。

### 调试参数

| 参数 | 说明 |
| --- | --- |
| `memlimit=<MB>` | 覆盖预算（如 `?memlimit=5` 让 18 MB 的文件也触发弹窗） |
| `memauto=sample` + `mempct=<N>` | 不弹窗，直接按 N% 下采样（自动化 / 演示） |
| `memauto=full` | 不弹窗，直接全量导入 |

## 4. 大文件策略

**默认不做任何数量限制**——载入多少就显示多少（`DEFAULT_MAX_TRIANGLES / DEFAULT_MAX_POINTS = Infinity`）。

| 项 | 默认值 | 生效位置 |
| --- | --- | --- |
| 最大三角形数 | **不限制** | `js/loaders.js` → `DEFAULT_MAX_TRIANGLES` |
| 最大点数 | **不限制** | `js/loaders.js` → `DEFAULT_MAX_POINTS` |
| 法向显示 | **不抽稀** | `js/renderer.js` → `ensureNormals`（`maxFaces = Infinity`） |
| 顶点显示 | **不抽稀** | `js/renderer.js` → `ensureVerts`（`maxVerts = Infinity`） |

需要限制时（超大数据遇到内存压力）可临时加 URL 参数，**只对本次生效**：

| 参数 | 说明 |
| --- | --- |
| `?maxtri=2000000` | 限制三角形数；二进制 STL 按**等间隔抽样**（保留完整三角面），属性面板显示“按 1/N 抽样” |
| `?maxpts=3000000` | 限制点数；文本点云按行截断并提示 |

- 读取与解析全部为分块异步，界面保持响应并显示进度条；
- 内存参考：约 1200 万三角形的 STL，顶点坐标占 ~430 MB（法向由着色器求导，不额外存储）；千万级点云再叠加 normals/tags/scalars 可达数百 MB，若浏览器提示内存不足，用上面的参数临时限量；
- **线框始终完整**（每个三角形 3 条边全部绘制，永不抽稀）。

## 5. 实现要点

### 5.1 渲染

| 主题 | 做法 |
| --- | --- |
| 顶点数据 | 载入后按量化坐标（`Q=1e4`，0.1 μm）**去重**，`posBuffer` 存唯一顶点 + `ELEMENT_ARRAY_BUFFER` 存索引（`drawElements`）；索引在 CPU 侧保留为 `srcIndex`，供线框/边界映射 |
| 面法向 | 不存法向，片元着色器用 `dFdx/dFdy` 对视图空间坐标求导得到面法向 |
| 正/背面 | 不透明图层**一次绘制**，着色器按 `gl_FrontFacing` 取 `uColor` 或 `uBackColor`；半透明图层仍分两遍（保证混合顺序） |
| 线框 | 按边键 `min*LIM+max`（`LIM=2^26`）**去重**，每条唯一边只画一次；退化三角形跳过 |
| 顶点显示 | 直接复用去重顶点（`0..vertCount-1`），不复制缓冲 |
| 共面叠加 | 面片 `polygonOffset(1.5, 2.0)` 后移，让线框/顶点/边界压在面上（不依赖视距） |
| 统计 | `stats.{triangles, draws, meshCalls, wireCalls, vertCalls, normalCalls, boundaryCalls}`，`?debug=1` 显示 |

### 5.2 边界

顶点按包围盒尺度量化去重 → 以 `a*LIM+b` 统计每条边被几个三角形使用 → **只出现 1 次**为开放边界。结果缓存在 `layer.gpu`，并转成独立 `LINES` VAO；绘制放在**每个视图末尾单独一遍**（关闭深度测试），避免被面片绘制状态吞掉。

### 5.3 拾取

- 屏幕坐标经相机自身基（`cam.basis()`，支持滚转）反投影成射线；
- **分块粗筛**：三角形数 ≥ 4000 时建立 `8×8×8` 网格，三角形按包围盒重叠注册；射线先与块 AABB 做 slab 求交，只对命中块内三角形跑 Möller–Trumbore；
- 点云按“点到射线距离 ≤ 包围球半径 × 1.2%”取最近；
- 结果用于三种场景：拾取信息、测量（距离/角度）、`Ctrl+左键` 与双击设旋转中心。

### 5.4 三维裁剪

选择多边形按当前视图**反投影为过视点的棱柱半空间**；网格对每个三角形依次裁剪（`segmented` 精确切口、`remaining` 差集分解，两部分不重叠不裂缝）；点云按半空间分类并保留法向/标签/标量。裁剪结果缓存在内存，点「应用拆分」才建图层。

### 5.5 视角器

正六面体削 8 角 + 削 12 棱，由半空间裁剪生成 **26 面**（6 正方形 + 12 矩形 + 8 正三角），面法向即 26 个标准视角；中心画 X/Y/Z 方向箭头（正对观察者时缩为圆点）。

### 5.6 相机

朝向用**四元数累积**（绕相机本地 right/up），无欧拉角死锁；`yaw/pitch` 作为派生属性，供 URL 参数、视角器、状态栏使用。

## 6. 示例：与本项目产物的配合

| 场景 | 做法 |
| --- | --- |
| 对比优化前后 | 「载入 两侧」同一个 STL → 左侧看原模型、右侧看 `_oh.obj`，视线同步 |
| 检查补洞质量 | 勾「边界」，未补好的孔会留下**明亮闭环** |
| 检查指定孔位 | 用「工具 → 裁剪 → 矩形/多边形」框住目标区域 → 应用拆分，只看该块 |
| 量取孔间距 | 「工具 → 拾取」点两个孔口边缘，面板直接给距离与 Δx/Δy/Δz |
| 大件打开慢 | 用 `?maxtri=` / `?maxpts=` 临时限量，或让下采样弹窗按比例抽样 |

## 7. 移植与部署

本目录**完全自包含，可直接复制到任意目录使用**：

| 项 | 说明 |
| --- | --- |
| 依赖 | 仅浏览器（需支持 WebGL2，Chrome / Edge 均可）；**无 CDN、无第三方库、无构建步骤** |
| 路径 | 全部相对路径，代码中无绝对路径、无项目名硬编码；中文/空格/任意磁盘路径均可 |
| 直接打开 | 双击 `index.html` 即可（`file://`）：载入、拖放、双视图、树、颜色、线框/顶点/法向、截图全部可用 |
| `file://` 限制 | ① 写入剪贴板被浏览器禁止（截图仍会下载）；② `?url=` 读取本地文件被 CORS 阻止；③ 无法使用 Web Worker |
| 需要上述能力时 | 双击 `serve.bat`（<http://127.0.0.1:8765/>，`server/serve.py` 一个进程同时提供页面与 `/optimize`） |
| 孔位优化（可选） | 额外需要 Python 3（仅标准库）+ 已构建的 `HoleOptimize_cli.exe`；不用时整个 `server/` 可删 |

## 8. 工程约定（目录 / 落位 / 维护）

> 目的：功能持续增加时结构不随代码量变乱。**新增文件前对照本节**。

### 8.1 目录职责

| 路径 | 该放什么 | 不该放什么 |
| --- | --- | --- |
| `js/core.js` | **L1 基础**：Vec3 / Mat4 / Quat / BBox / OrbitCamera | DOM、GL、业务状态 |
| `js/io.js` | **L2 IO**：格式解析（STL/OBJ/PLY/点云）+ 孔位优化调用 + 载入前规模估算 | 渲染、界面布局 |
| `js/algo.js` | **L3 算法**：三维裁剪、拾取与测量 | GL、DOM（App 方法由 app 启动时注入） |
| `js/render.js` | **L4 渲染**：WebGL 管线 + 视角器 | 图层管理、业务规则 |
| `js/ui.js` | **L5 界面**：场景树 / 属性面板 / 视图设置 / 弹窗 / 全局拖放 | GL 细节、算法实现 |
| `js/app.js` | **L6 编排**：状态、图层、视图调度、输入分派、渲染循环、URL 参数（`MV.config`） | 具体算法与 DOM 细节 |
| `server/` | 本地服务（静态 + `/optimize`）、独立桥接、端到端自测 | 任何前端代码 |

**分层契约**：`ui → app → {algo, render, io}`，`{algo, render, io} → core`。下层**不得**直接调 `MV.ui`——通过 `bindHooks()` 注入的 `notify / refreshProps / renderPickBar` 通知，`App.prototype` 方法经 `installAppMethods()` 注入。

**根目录白名单**：`index.html`、`README.md`、`CHANGELOG.md`、`.gitignore`、`serve.bat`、`check.ps1`、`css/`、`js/`、`server/`。

### 8.2 落位判断（新增功能三步）

1. 问「它属于哪一类」：**I/O 解析 / 渲染 / 编辑算法 / 界面 / 编排**；
2. 能放进现有某一层 → 放进去；
3. 放不进（如“布尔运算”“点云配准”）→ **新建平级文件/目录**，禁止继续塞进 `app.js`。

### 8.3 规模阈值（量化）

| 信号 | 动作 |
| --- | --- |
| 单文件 > 800 行 | 记入待办，下次改动该文件时按职责拆 |
| 单文件 > 1,500 行 | **必须拆**（当前 `io.js` 1,668 / `ui.js` 1,663 / `render.js` 1,947 已越线） |
| 单函数 > 150 行 | 拆函数（`ui.js init()` 553 行是当前最大债） |
| `js/` 文件数 > 12 | 建子目录分组 |
| 目录深度 > 3 层 | 停止加深，改为按文件拆分 |

### 8.4 命名与加载

| 约定 | 说明 |
| --- | --- |
| 文件名 | 小写 + 语义（`segment` ✅ / `utils2` ❌） |
| 全局命名空间 | 每文件 IIFE 暴露 `MV.<层>`；加载顺序 `core → io → algo → render → ui → app` |
| 入口唯一 | 对外只暴露 `serve.bat`；`server/start_bridge.bat` 仅作 `file://` 兜底 |
| 不使用 ESM / 构建工具 | 保证 `file://` 双击可用（ESM 会被 CORS 拦截），保持零依赖零构建 |
| URL 参数 | 统一在 `app.init()` 解析成 `MV.config`，其它模块只读配置 |

### 8.5 临时文件

- 临时脚本、截图、dump 产物**一律放 `_t/`**（已在 `.gitignore`）；
- 根目录出现 `_*.py` / `_*.png` / `_tmp*/` 视为违规；
- 运行产物 `server/bridge.log`、`__pycache__/`、`*.pyc` 已忽略。

### 8.6 文档维护

| 文件 | 何时更新 |
| --- | --- |
| `CHANGELOG.md` | **每次可感知改动**：递增版本号并追加条目，修复类必须写**根因** |
| `README.md` | 新增功能 / 参数 / 交互时同步；顶层目录变化时更新 8.1 |
| 帮助面板（`index.html`） | 新增快捷键或鼠标手势时同步 |

### 8.7 何时重构（触发清单）

- 新增功能都想往 `app.js` 里塞；
- 改一个功能要在 3 个以上文件来回跳；
- 同一概念出现两套实现；
- 出现“改这里会坏那里”的恐惧感。

满足任一条即安排一次小步重构，**不要等乱到无法改**。
